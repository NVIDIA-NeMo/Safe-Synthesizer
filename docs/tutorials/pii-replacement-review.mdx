#### What you'll learn

Before training, NeMo Safe Synthesizer replaces personally identifiable information (PII) in your data. An LLM drafts the replacement plan: which columns hold PII, what kind of PII each one holds, and how the new values should be generated. In this notebook, you'll draft that plan without training anything, review it, edit it if needed, and then train with exactly the plan you reviewed.

The example also shows how to keep a column the LLM marks as PII. The simulated hospital wants to compare readmission rates by attending physician, so it keeps the physicians' names instead of replacing them.

The steps are:

1. Draft the plan from the data with `plan_pii_replacement()`.
2. Review the saved plan file, `pii_replacement_plan.yaml`.
3. Edit the file to correct the plan or keep a column you need.
4. Run the pipeline with the reviewed file and check the PII results in the evaluation report.

> Runtime: Running the complete notebook takes about an hour on an NVIDIA A100, most of it fine-tuning. A first run may take longer while model files are downloaded.

> The dataset used here is the simulated hospital admissions dataset from the [Healthcare Hospital Readmissions](/tutorials/healthcare-hospital-readmissions) tutorial. It was generated with [NVIDIA NeMo Data Designer](https://docs.nvidia.com/nemo/datadesigner/getting-started/welcome) and contains no real patient data.

Pandas infers quoted numeric CSV fields as integers, so the explicit string dtype below preserves leading zeros in postal codes.

while len(physicians) < 100:
    name = f"{fake.first_name()} {fake.last_name()}"
    if name not in physicians:

source_df.insert(
    source_df.columns.get_loc("full_name") + 1,
    "attending_physician",
    rng.choice(physicians, size=len(source_df), p=rng.dirichlet(np.full(len(physicians), 2.0))),

## 5. Review the plan

The plan is a draft from an LLM, so check it against what you know about the data. The file has two sections, each with a short comment above it:

- `columns_to_replace` lists the columns whose values are replaced. Every column not listed is kept unchanged.
- `data_to_sampler_value_mapping` translates values of the columns that guide a replacement, such as `sex`, to values the sampler understands. Safe Synthesizer fills it in.

The header names the sampler and locale the plan was written for. Those are set in the configuration as `replace_pii.sampler` and `replace_pii.locale`, not in this file.

Check the plan:

- **Nothing sensitive is kept.** Every identifier, name, contact detail, street address, and date of birth should be in `columns_to_replace`. A sensitive column left out reaches the model as is.
- **Nothing is replaced that you need to keep.** Clinical fields such as diagnosis, labs, and charges should not be in the plan. Neither should a column you decide to keep, such as `attending_physician` in this example.
- **Each `entity_type` is right.** It decides what kind of value is generated, for example `full_name` or `unique_identifier`.
- **Each `pattern` keeps the format you need.** An optional `pattern` sets the format of the new values. Without one, an identifier gets random letters and digits in the original's layout, so a fixed prefix such as `MRN-` is not kept.
- **The `depends_on` links make sense.** They list the columns a replacement follows, for example an email built from the replaced name, or a name chosen to match `sex`. A missing link means those values are replaced independently, so they may no longer match.
- **Free text is scanned.** Written notes such as `discharge_summary` should be listed with `entity_type: free_text`, so names and other PII inside them are found and replaced.

Some kinds of values are never replaced as whole columns: cities, states, ZIP codes, countries, organizations, genders, ethnicities, and ordinary dates such as admission dates. They stay out of the plan by design, and the plan may use them to guide other replacements.

## 6. Edit the plan

To change the plan, edit `pii_replacement_plan.yaml` at the path the draft cell printed, then rerun the display cell above to see the result.

**Remove `attending_physician` from the plan.** This step is required in this example. The LLM most likely lists `attending_physician` as a name to replace, because it holds people's names. To keep the original names for analytics by physician, delete the whole entry. Your draft may differ: the entry may say `entity_type: free_text` instead, or have no `depends_on` lines. It often looks like this, with `depends_on` lines that link the physician's name to the patient's sex and ethnicity:

```yaml
- column_name: attending_physician
  entity_type: full_name
  depends_on:
  - column_name: sex
    entity_type: gender
  - column_name: race_ethnicity
    entity_type: ethnic_background
```

A kept column reaches the model unchanged, so its values can appear in the synthetic data. Keep a column of names only when your data-sharing rules allow those names to be shared. If the plan does not list `attending_physician`, there is nothing to delete.

Other edits you may need:

- **Columns:** add, remove, or correct entries in `columns_to_replace`. For example, to keep the `MRN-` prefix of medical record numbers such as `MRN-4C806C7840`, give the `mrn` entry a pattern. `&` stands for a digit or an uppercase letter, and `#` for a digit:

  ```yaml
  - column_name: mrn
    entity_type: unique_identifier
    pattern: MRN-&&&&&&&&&&
  ```

- **Value mapping:** in `data_to_sampler_value_mapping`, map each value as it appears in your data to one or more values the sampler accepts. Gender uses `female` and `male` for every sampler. Matching ignores case, and a value mapped to several sampler values can draw from any of them. For example:

  ```yaml
  data_to_sampler_value_mapping:
    sex:
      W: [female]
      Unknown: [female, male]
  ```

When the plan is right, run the next cell. It loads and checks the file, and stops if `attending_physician` is still listed. A sampler value with a typo stops with a message naming it. A value in a guiding column that matches no sampler value and has no entry also stops, with a message giving the column and how many values are missing.

```python
# Use the reviewed file. Its plan is no longer a draft, so the planning LLM does not run again.
builder = builder.with_replace_pii(replacement_plan=str(PLAN_PATH), seed=SPLIT_SEED)
reviewed = builder.plan_pii_replacement().inline_plan
if any(column.column_name == "attending_physician" for column in reviewed.columns_to_replace):
    raise ValueError(
        f"attending_physician is still in the plan. Delete its entry from {PLAN_PATH}, save the file, "
        "and rerun this cell."
    )
print(f"Using the reviewed plan: {len(reviewed.columns_to_replace)} columns will be replaced.")
print("attending_physician is kept unchanged.")
```

## 10. Compare admissions by physician

Because `attending_physician` was kept, the synthetic data uses the same physician names, so per-physician analytics work on it. The next cell compares each physician's share of admissions and 30-day readmission rate in the source and synthetic data, for the 10 physicians with the most admissions. Rates for a single physician rest on about a hundred admissions, so expect them to differ by several points.

```python
def by_physician(df: pd.DataFrame) -> pd.DataFrame:
    # The synthetic data may hold the flag as text, so compare as text.
    readmitted = df["readmitted_within_30_days"].astype(str).eq("True")
    grouped = readmitted.groupby(df["attending_physician"])
    return pd.DataFrame({"Share of admissions": grouped.size() / len(df), "Readmission rate": grouped.mean()})


comparison = pd.concat(
    {"Source": by_physician(source_df), "Synthetic": by_physician(results.synthetic_data)}, axis=1
)
comparison = comparison.sort_values(("Source", "Share of admissions"), ascending=False).head(10)
display(comparison.style.format("{:.1%}", na_rep="-"))
```

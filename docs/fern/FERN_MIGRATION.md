when the migration is complete; see [CONTRIBUTING.md](../../CONTRIBUTING.md#fern-validation-and-previews)

## Current status

The initial MDX content, Fern configuration, notebook exporter, and validation
and manual preview workflows are present in the repository. MkDocs and mike
still serve the production site and release documentation.

Fern currently configures only `nightly`, with the preview instance
`nemo-safe-synthesizer.docs.buildwithfern.com`. Confirmation of the instance,
official production URL, and token provisioning with the NVIDIA Fern team is
still needed. Production publishing and frozen Fern release versions are not
configured.

The API Reference entry is omitted pending generated API pages; inline Python
symbol names currently have no API links. Tutorial notebooks have static MDX
companions, but their handling and rendering need further work. Historical
versions remain on GitHub Pages.

## Required during migration: update both formats

Every change to a paired documentation page must update both its `.md` and
`.mdx` files in the same change. These are independent sources with no automatic
prose synchronization: `.md` serves production MkDocs and `.mdx` serves Fern.
Keep the content equivalent using each renderer's syntax.

- New prose pages need both formats and matching navigation entries in
  `mkdocs.yml` and `docs/fern/versions/nightly.yml`.
- For notebooks, edit `.ipynb`, run `mise run docs:fern:notebooks`, and review
  and include the generated MDX. Do not edit generated notebook MDX directly.
- Standalone maintainer/repository Markdown, including this file, does not need
  an MDX counterpart. Do not update frozen release snapshots for routine changes.
- Verify both renderers with `mise run docs:build` and
  `mise run docs:fern:check`, and preview affected pages in both sites.
- Retain legacy pages, configuration, and shared assets until cutover and cleanup.

## Before publication and cleanup

Review the hosted preview for content and visual parity, including navigation,
search, API coverage and anchors, and notebook rendering and downloads. The API
work must restore the reference navigation and symbol links, including Pydantic
field documentation currently generated by mkdocstrings.

Production automation must validate before publishing and preserve frozen
release versions. Keep publishing credentials out of untrusted PR execution;
tokenless PR checks should continue to work. Retain the existing policy of
publishing release docs for final releases, including post-releases, rather
than prereleases.

Before switching public links, inventory important page URLs and anchors,
verify their destinations, and retain a known-good MkDocs deployment for
rollback. Keep historical GitHub Pages releases and their assets serving at
their existing URLs. Any redirects for old main/latest pages need explicit
route and anchor checks; Fern redirects cannot handle requests to another host.

After the public site, links, and release publishing have been verified, stop
routine MkDocs and mike deployments while preserving the existing GitHub Pages
site. Remove only legacy pages with verified MDX replacements, obsolete MkDocs
configuration, tasks, assets, and dependencies. Keep shared assets, notebooks,
and repository Markdown. Remove temporary dual-authoring guidance from
`CONTRIBUTING.md`, `AGENTS.md`, and `STYLE_GUIDE.md`, then delete this file.

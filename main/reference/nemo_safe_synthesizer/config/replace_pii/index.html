    replace_pii

    replace_pii ¶

    Dataset-specific PII detection/replacement plan.

    This is the declarative, column-oriented plan a user (or an upstream detector) provides to describe how to replace PII in a dataset.

    Every label is an Entity with an EntityAction and whether it can_condition other columns. User-facing plans name the entity on each replace target and on read-only depends_on entries. A conditioner that is also a replace target inherits the entity from that target.

    columns_to_replace pydantic-field ¶

    Columns to replace or (for free_text) scan for PII spans to rewrite.

    data_to_sampler_value_mapping pydantic-field ¶

    Maps dataset values in depends_on columns to the values used by replace_pii.sampler. Unlike most NSS settings, all matching here ignores case: dataset values, mapping keys, and sampler values, so Female, female, and FEMALE are the same value. For example, {sex: {Woman: [female], Non-binary: [female, male]}} makes rows where sex is Woman sample a female persona and rows where sex is Non-binary sample either. Gender values are female and male for every sampler; Nemotron-Personas also accepts its locale's own words, such as femme in fr_FR. Ethnicity values need Nemotron-Personas in a locale with ethnicity data. A dataset value without an entry is looked up in the sampler as is; a value that has no entry and matches no sampler value is an error. When replace_pii.replacement_plan is 'auto_discovery', NSS generates this mapping for you.

    def replacement_order(self) -> tuple[PiiColumnPlan, ...]:
    """Return ``columns_to_replace`` so every column comes after the columns it depends on.

    Independent columns keep their listed order. Dependencies on columns that are not replaced
    do not affect the order.

    Raises:
        ParameterError: If the dependencies form a cycle; the message names the columns in it.
    """
    specs = self.columns_to_replace
    by_name = {spec.column_name: spec for spec in specs}
    position = {spec.column_name: index for index, spec in enumerate(specs)}
    outgoing: dict[str, set[str]] = {column: set() for column in by_name}
    indegree = dict.fromkeys(by_name, 0)
    for spec in specs:
        for dependency in spec.depends_on:
            source = dependency.column_name
            if source not in by_name or spec.column_name in outgoing[source]:
                continue
            outgoing[source].add(spec.column_name)
            indegree[spec.column_name] += 1

    ready = [(position[column], column) for column, degree in indegree.items() if degree == 0]
    heapq.heapify(ready)
    ordered: list[PiiColumnPlan] = []
    while ready:
        _, source = heapq.heappop(ready)
        ordered.append(by_name[source])
        for target in outgoing[source]:
            indegree[target] -= 1
            if indegree[target] == 0:
                heapq.heappush(ready, (position[target], target))

    if len(ordered) != len(by_name):
        cycle_columns = sorted(column for column, degree in indegree.items() if degree > 0)
        raise ParameterError(
            "replacement dependencies contain a cycle involving: "
            + ", ".join(repr(column) for column in cycle_columns)
        )
    return tuple(ordered)

    entity_thresholds pydantic-field ¶

    Minimum GLiNER2 confidence score per entity type. Entity types left out use the defaults: 0.944 for first_name; 0.7 for middle_name; 0.614 for last_name; 0.963 for full_name; 0.992 for phone_number; 0.9998 for date_of_birth; 0.987 for street_address; 0.979 for national_id; 0.991 for api_key; and 0.946 for unique_identifier. Email, credit_debit_card, ipv4, and ipv6 are detected by regex and take no threshold.

    checked_national_id_threshold = _DEFAULT_CHECKED_NATIONAL_ID_THRESHOLD pydantic-field ¶

    Minimum GLiNER2 confidence score for a detected national ID that python-stdnum accepts as a personal ID of replace_pii.locale's country, such as a US Social Security number for en_US. It replaces entity_thresholds.national_id for those values, since the check rather than the score tells them apart. Locales without a check, such as en_GB, use only the national_id threshold.

    name_exclusion_thresholds pydantic-field ¶

    Extra GLiNER2 labels, with their minimum confidence, for terms often mistaken for names, such as medical conditions or family relationships. A detected name that overlaps one of these spans is not replaced, and find_and_replace does not replace text inside them. Labels you set are merged into the defaults; set a label to null to drop it, and it stays null in the configuration. Dropping every label turns exclusion off, which finds more real names at the cost of more false names in clinical text.

    find_and_replace = True pydantic-field ¶

    Search free text for values already known in the same record or group and replace the occurrences the detectors missed. Detected spans reuse a known value's replacement either way; this setting only adds the search. Known values are original values of structured replacement columns, including the words of a plain full name, and values detected elsewhere in free text. Only whole words are matched, ignoring case. Values shorter than three characters, one-word values that are common English words, such as 'Will' or 'Brown', and missing-value placeholders such as 'Unknown' are not searched for, and text inside a name-exclusion span, such as a medical condition, is never replaced this way. Set false to replace only detected spans, for example to measure what the search adds. The search runs only when replace_pii.locale is en_US, because the common-word list is English.

    Number of text chunks processed in one GLiNER2 inference batch. Must be positive.

    chunk_length = 384 pydantic-field ¶

    Maximum length of each GLiNER2 text chunk. Must be positive.

    chunk_overlap = 128 pydantic-field ¶

    ReplacePiiConfig pydantic-model ¶

    Bases: Parameters

    Top-level replace_pii config.

    replacement_plan holds what a person reviews: the columns to replace and the value mapping. It is "auto_discovery" (the default), an inline plan, or the path of a YAML plan file, resolved relative to the configuration file that names it. locale, seed, and sampler configure generation; a plan's value mapping is checked against the sampler and locale of each run. llm and free_text_detection configure how NSS finds PII.

    Auto-discovery classifies columns with the LLM configured by llm, which defaults to the NSS inference defaults. An inline plan bypasses discovery, so it makes no LLM request; that is the way to replace PII without an LLM. The API key remains a runtime secret supplied through NSS_INFERENCE_KEY or the corresponding CLI option; it is never stored in this model.

    def validate_dependency_relationship(
    target_entity_type: EntityType,
    source_entity_type: EntityType | None,
    *,
    target_column: str,
) -> None:
    """Validate one dependency edge against the entity relationship catalog.

    A missing source type is deferred until ``PiiReplacementPlan`` can infer it
    from the complete replacement graph; the target must still support
    dependencies at this earlier validation seam.
    """
    allowed = ALLOWED_DEPENDS_ON.get(target_entity_type, frozenset())
    if not allowed:
        raise ParameterError(
            f"column {target_column!r}: entity_type {target_entity_type.value!r} does not allow depends_on"
        )
    if source_entity_type is None or source_entity_type in allowed:
        return
    raise ParameterError(
        f"column {target_column!r}: depends_on entity_type "
        f"{source_entity_type.value!r} is not allowed for entity_type "
        f"{target_entity_type.value!r} (allowed: {sorted(entity.value for entity in allowed)})"
    )
